# Backend «Зона 9»

Исходник FastAPI, PostgreSQL и aiogram. Интеграция игрового источника **не подключена**: игровые учётные данные не предоставлены, живые ответы не проверены. В production нет демонстрационных профилей и обхода Telegram-авторизации. `GET /api/status` явно сообщает состояние источника. `GET /healthz` проверяет базу, отдельно сообщает доступность источника; healthy не означает, что игровой источник уже настроен.

Python 3.12, PostgreSQL 16+. Из каталога `backend`:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
python -m app.worker
python -m app.bot
```

Каждая из трёх последних команд запускается отдельным управляемым сервисом. Единственный API-процесс ограничивает холодные разрешения UID; единственный worker последовательно обновляет историю с паузой и повторами до трёх попыток. PostgreSQL advisory locks предотвращают конкурирующие worker и polling-процессы этого проекта. При обнаружении уже настроенного webhook бот прекращает запуск, не удаляя его. Не запускайте другой polling-сервис с тем же токеном. Перед PostgreSQL-миграцией production сделайте резервную копию; тесты миграций используют отдельную временную SQLite-базу.

Параметры окружения:

| Имя | Назначение |
|---|---|
| DATABASE_URL | SQLAlchemy URL отдельной PostgreSQL базы, `postgresql+psycopg://…` |
| BOT_TOKEN | Токен именно этого бота, только backend/bot |
| BOT_USERNAME | Имя бота без `@` |
| PUBLIC_URL | HTTPS-адрес frontend Mini App; источник кнопок бота и разрешённого origin изменений |
| ALLOWED_ORIGINS | Разрешённые frontend origins через запятую, без пути и `*` |
| AUTH_MAX_AGE | Максимальный возраст исходного Telegram initData; по умолчанию 300 секунд |
| SESSION_TTL | Срок серверной сессии; по умолчанию 43200 секунд |
| REFRESH_TTL | Свежесть кэша; по умолчанию 300 секунд |
| SOURCE_TIMEOUT | Тайм-аут отдельного запроса; по умолчанию 30 секунд |
| SOURCE_MIN_INTERVAL | Пауза между запросами источника; по умолчанию 2 секунды |
| HISTORY_MAX_PAGES | Защитный максимум проверенных страниц за одно обновление; по умолчанию 10 |
| SOURCE_ADAPTER | `module:factory` проверенного адаптера, по умолчанию пусто |

Секреты передавайте только окружением или серверным env-файлом с правами 0600; не храните в Git. Секреты не нужны в браузере.

`POST /api/auth` принимает `{init_data}` и проверяет HMAC Telegram, токен бота, `auth_date`, повторяющиеся поля и числовой ID пользователя. Возвращает `{primary_uid,mode,session_token,expires_in}`. Клиент хранит session_token только в оперативной памяти и отправляет `Authorization: Bearer …`. В базе хранится SHA-256 токена, сессия ограничена по времени. При повторном открытии старые сессии пользователя заменяются. Дополнительно устанавливается Secure HttpOnly SameSite=Lax cookie для same-origin варианта. Для GitHub Pages/separate backend используется Bearer, не сторонние cookie. Production не имеет debug login. CORS разрешён только указанным ALLOWED_ORIGINS, изменяющие запросы с посторонним Origin отвергаются. Telegram ID из URL или тела не используется для владельца настроек.

API `/api/me`, `/api/players/{uid}`, `/api/players/{uid}/refresh`, `/api/matches/{id}?uid=…`, `/api/top` требует сессию. Поиск чужого публичного UID не меняет основной профиль и не открывает чужие настройки. Изменение основного ID проходит через `PUT /api/me {primary_uid}` после проверки существования профиля в источнике или сохранённого подтверждённого соответствия UID. Эта привязка обозначает предпочтение просмотра, не владение игровым аккаунтом.

Архив сохраняется без автоматического удаления. Матчи дедуплицируются по ID, участия — по паре матч/игрок. Режимы разделены. Сохраняются только компактные метрики; сырые сетевые дампы не складируются. На открытии отдаётся сохранённый профиль немедленно, устаревший профиль получает задачу в БД. Повторные запросы одной пары UID/режим объединяются. Основной показатель всегда последние 20 завершённых матчей; `scope=archive` меняет только список для графика, не сводку. При более 10000 сохранённых игр endpoint явно возвращает `archive_truncated=true`, записи базы не удаляются. Топ кэшируется на 30 секунд и использует оконный SQL-запрос по последним 20 матчам каждого отслеживаемого основного профиля.

Пагинация выключена, пока реальный адаптер не подтвердит её. Отсутствие пересечения последовательных доступных окон фиксирует возможный пробел с временными границами. При пагинации проверяется вся успешно загруженная цепочка, чтобы не помечать перекрытый страницами участок ложным пробелом. Нет обещания восстановить игры, отсутствующие на сервере источника. Количество пропущенных игр не выдумывается. После перезапуска прерванные задания безопасно повторяются, обработка атомарна. Ошибки источника не стирают кэш; подробные исключения не пишутся в базу и логи.

Интерфейс адаптера — `app/source.py`: `resolve_uid` обязан явно разрешать публичный UID во внутренний `source_id`, `fetch_history` возвращает только проверенные поля с `None` для отсутствующих значений. `rounds` — личные сыгранные раунды; профильный HS% не подходит для статистики матча. До включения адаптера нужны обезличенные реальные ответы, проверка типов, режимов, пагинации и ограничения частоты. Источник со `supports_pagination=False` никогда не опрашивается с выдуманным offset.

Проверки:

```sh
pytest tests -q
python -m app.recalculate
```

Тесты используют изолированную SQLite-базу и явно тестовый источник, без обращения к игре и Telegram. Они проверяют арифметику рейтинга, цвета, суммарные метрики, авторизацию, разделение настроек, режимы, дедупликацию, кэш, очередь и пропуски. Они не доказывают доступность реального Standoff-источника. Формула и ограничения описаны в `docs/rating.md` корня проекта.
