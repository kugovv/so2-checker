# Проверка источника Standoff 2

Проверено 15.11.2026. **Авторизованных ответов игрового сервера пока не получено:** предоставлены доступ к VPS и токен Telegram-бота, но отсутствует handshake игровой сессии. Таблица ниже описывает найденную схему клиента, а не подтверждённые живыми ответами возможности. Производственный источник остаётся отключённым; вместо статистики показывается состояние недоступности.

Пакет PyPI `0.3.0.2` дополнительно установлен в изолированный локальный каталог: импорт `StandClient`, создание protobuf-запросов UID/истории и сборщик схемы probe проходят в Python 3.12.10. Сетевое подключение и актуальная совместимость с игрой не подтверждены.

## Первоисточники и воспроизводимость

- [AstandyClient](https://github.com/BonePolk/AstandyClient), main, SHA `2976a676e199d6f51959ceacc6016b3d127cd12d`. README требует handshake игрового аккаунта. Он ограничен по времени; вход через официальный игровой клиент инвалидирует предыдущую сессию.
- [PyPI astandy](https://pypi.org/project/astandy/) и [машиночитаемые метаданные](https://pypi.org/pypi/astandy/json): актуальный опубликованный пакет `0.3.0.2`, 10.06.2026, Python >=3.10. SHA-256 архива: `04cd175a84b4e600feb7b10701cc4d6bf88fb1d78e935c3723b9f96eee6483b2`.
- [Документация](https://astandyclient.readthedocs.io/en/latest/) и [примеры](https://astandyclient.readthedocs.io/en/latest/examples/) используют `client.raw.<Service>.<method>(client, protobuf_request)`.
- [so2checker_bot](https://t.me/so2checker_bot) — отдельная публичная страница бота Telegram. Его фактическая работа из нашей сессии не проверена. Страница не предоставляет его закрытый API, токен или игровую сессию.

Локально исследованы исходники опубликованного PyPI-архива. Его protobuf-файлы содержатся в `research/astandy-0.3.0.2/Astandy/generated/protos`. Машинная сводка дескрипторов: `research/astandy-descriptors.json`, генератор: `research/inspect-descriptors.cjs`. В GitHub main отсутствуют некоторые импортируемые сгенерированные файлы, включая `generated/protos` и `types/rpc_target.py`; в PyPI `0.3.0.2` они присутствуют. Поэтому устанавливать GitHub main вместо проверенного релиза вслепую нельзя. Ни дата релиза, ни наличие схемы сами по себе не доказывают совместимость с текущим сервером игры.

## Что требуется для подключения

Нужен действующий handshake отдельного разрешённого игрового аккаунта либо документированный авторизованный API-провайдер с доступом к данным. SSH-пароль относится к VPS, токен Telegram — к Telegram Bot API; ни один из них не заменяет игровую авторизацию. В предоставленных инструментах нет средства самостоятельно авторизовать игровой аккаунт. Для живого теста дополнительно нужен существующий публичный игровой UID с матчами обоих режимов.

В клиенте соединение настроено на TLS `server.boltgaming.io:2223`; затем выполняются `hello` и `encryptedHandshake(Handshake(ticket=...))`. Библиотека использует встроенный сертификат CA. Не отключать проверку сертификатов. Handshake передавать через закрытый серверный файл; не через командную строку, stdout или frontend.

## Схема и ограничения

Во всех строках фактическая обязательность присутствия в живом ответе пока **не проверена**. Proto3 не гарантирует присутствия значения только потому, что поле объявлено; скалярный ноль, false и пустая строка могут отсутствовать на проводе. У динамического `Property.value` есть `oneof`, что позволяет отличить отсутствие значения от переданного нуля.

| Данные | Точное поле в опубликованной схеме | Тип / смысл | Область | Поведение при отсутствии |
|---|---|---|---|---|
| Публичный игровой ID | `Player.uid`, `MatchPlayer.uid` | string, отображаемый UID | профиль / участник матча | Не подставлять внутренний ID; профиль без корректного UID не закреплять |
| Внутренний ID | `Player.gpid`, `MatchPlayer.gpid` | string, внутренний идентификатор | профиль / участник | UID сначала разрешается отдельным запросом; без результата история не запрашивается |
| Ник | `Player.name`, `MatchPlayer.name` | string | профиль / участник | Показать UID, не придумывать ник |
| ID аватара | `Player.avatarId`, `MatchPlayer.avatarId` | string, идентификатор ресурса, не URL | профиль / участник | Локальная заглушка; не использовать ID как URL |
| Бинарный аватар | `GetAvatarsResponse.avatarBinaries[].avatar` | bytes, запрос `GetAvatarsRequest.avatarIds` | ресурс | Тип/размер проверять перед выдачей; при недоступности заглушка |
| Выбранный агент | Отдельного поля в изученной схеме не найдено | Семантика dynamic attributes неизвестна | неизвестно | Не показывать агента |
| ID матча | `FinishedMatch.matchId` | string, ключ дедупликации | матч | Матч без стабильного ID не учитывать |
| Даты | `FinishedMatch.startDate`, `finishDate` | int64, единицы измерения ещё нужно проверить | матч | Не выдумывать дату; не считать секунды/миллисекунды без проверки |
| Сезон | `FinishedMatch.seasonId`; `Stats.seasonId` | string | матч / агрегаты сезона | Не смешивать сезонную метрику с матчевой |
| Статус | `FinishedMatch.state` | enum `FINISHED=0`, `CANCELED=1`, `ANNULLED=2` | матч | Исключать отменённые и аннулированные по одинаковому правилу; проверить default enum в живом ответе |
| Тип матча | `FinishedMatch.matchType` | enum `REGULAR=0`, `CLAN_BATTLE=1`; **это не режим 5×5/2×2** | матч | Не использовать для определения режима |
| Участники | `FinishedMatch.players[]`; при клановом матче также `clans[].players[]` | repeated `MatchPlayer` | матч | Показывать лишь имеющихся участников; не выдумывать состав |
| Карта | Фиксированного поля нет; возможный контейнер `FinishedMatch.properties[]` | динамический `Property` | матч, точный ключ неизвестен | «Нет данных» |
| Режим 5×5/2×2 | Фиксированного поля нет; `FinishedMatch.properties[]` | динамический `Property`, точный ключ и значения неизвестны | матч | Матч с неподтверждённым режимом не включать ни в одну выборку |
| Итоговый счёт | Фиксированного поля нет; `FinishedMatch.properties[]` | точные ключи неизвестны | матч | «Нет данных», не выводить результат из K/D/A |
| Команды участников | Фиксированного поля команды нет; возможны `MatchPlayer.properties[]` | точный ключ неизвестен | участник матча | Общий список участников без вымышленного распределения |
| Убийства / смерти / ассисты | Фиксированных полей нет; возможны `MatchPlayer.properties[]`, `reward.stats[]` | динамические ключи и семантика ещё не проверены | нельзя определить без живых ответов | Нет рейтинга при отсутствии обязательных K/D/A; не подставлять нули |
| Убийства в голову | Фиксированного поля нет | точный ключ неизвестен | неизвестно | Скрыть HS% матча/выборки; не заменять общим HS% |
| Раунды игрока | Фиксированного поля нет | точный ключ неизвестен | участник матча | Не выдавать сумму счёта матча за личные раунды; только отдельно обозначенная упрощённая оценка |
| Игровые очки / место | Фиксированных полей нет | точные ключи неизвестны | участник матча | Скрыть; не добавлять скрытый бонус |
| Исторический MMR до/после | Фиксированных полей нет; `MatchPlayer.reward.stats[]` — лишь кандидат | `PlayerStat.name/type/intValue/floatValue/longValue`, смысл ключей неизвестен | неизвестно | Без поправки силы соперников и без исторического MMR-графика |
| Текущий MMR | Фиксированного поля нет; возможны `Player.attributes.map`, `PlayerStats.stats.stat[]` | ключи неизвестны; `Stats` содержит `seasonId`, `updatedDate` | профиль / сезон, не исторический матч | «Нет данных»; не подставлять как MMR в прошлом |
| Урон / ADR / событийные метрики | Подтверждённых полей и событийных ответов нет | неизвестно | неизвестно | ADR, KAST, opening/exit kills, размены не рассчитывать |
| Статистика других участников | Контейнер `FinishedMatch.players[].properties[]` есть в схеме | наличие и полнота живых показателей неизвестны | участник матча | Только фактически присутствующие показатели |
| История дальше 20 | `GetPlayerMatchesRequest.offset` → `Offset.offset`, `Offset.length` | int32 смещение и размер; ограничение сервера неизвестно | запрос истории | Не обещать архив; сохранить обнаруженные игры и явно отмечать пробелы |

Динамические свойства имеют `name`, enum `type` и одно значение из `intValue`, `floatValue`, `longValue`, `stringValue`, `booleanValue`. В `PlayerStat` поля значений не образуют oneof; отсутствие числового wire-поля нельзя автоматически считать отсутствием статистики или настоящим нулём. `MatchPlayer.reward.stats` по названию относится к награде/изменению статистики, но без живых ответов нельзя считать каждый показатель финальной статистикой матча.

## Разрешение UID и проверка пагинации

Правильная последовательность: `PlayerRemoteService.getPlayerByUid(GetPlayerByUidRequest(uid=публичный_ID))` → `response.player.gpid` → `MatchesRemoteService.getPlayerMatches(GetPlayerMatchesRequest(gpid=внутренний_ID, offset=Offset(offset=0,length=20)))`. Сохранять публичный UID и внутренний gpid отдельно. Возвращённый `player.uid` должен совпадать с запрошенным.

`tools/probe_source.py` выполняет только чтение: авторизуется, разрешает UID, запрашивает offsets 0/20/40 по 20 матчей без неподтверждённых фильтров и составляет отчёт о схемах, наличии полей, именах/типах динамических свойств, количестве/пересечении страниц. Полные ответы, ники, ID участников и значения динамических свойств в отчёт не включаются. Из-за неизвестного ключа режима эти страницы ещё не являются последними 20 матчами выбранного режима.

```sh
python3 -m venv /opt/so2-checker/source-probe-venv
/opt/so2-checker/source-probe-venv/bin/pip install 'astandy==0.3.0.2'
chmod 600 /etc/so2-checker/game-handshake
/opt/so2-checker/source-probe-venv/bin/python tools/probe_source.py \
  --handshake-file /etc/so2-checker/game-handshake \
  --uid PUBLIC_NUMERIC_UID \
  --report-out /opt/so2-checker/source-probe-report.json
```

Без handshake CLI завершится с кодом 2 и объяснением, без подключения к игре. После появления handshake проверить фактический import, TLS, успешную авторизацию, разрешение нескольких UID и независимость режимов. Пустой RPC-envelope, который библиотека способна вернуть после таймаута, probe трактует как ошибку; пустая транспортная заглушка не считается ответом с нулём матчей.

Один пустой offset=20 не доказывает общий лимит 20: аккаунт может иметь меньше игр. Новые IDs в следующих страницах подтверждают более глубокую историю только для проверенного аккаунта в момент теста. Повтор страницы при изменении offset — отдельное ограничение источника. Требуются проверки нескольких активных аккаунтов и дат, а затем одинаковый фильтр завершённости/режима.

## Что нужно до включения производственного адаптера

1. Получить успешные живые ответы и обновить таблицу точными ключами, единицами, значениями режимов и обязательностью. Не использовать догадки вида `kills`, `mode`, `rounds` как доказанные имена.
2. Проверить приращения `reward.stats` против финальных K/D/A; сопоставить один матч с игровым экраном. Выделить личные сыгранные раунды, поздние подключения и выходы. При отсутствии обязательных показателей рейтинг остаётся отсутствующим.
3. По проверенным ключам написать строгий адаптер в нормализованный формат приложения; неизвестные режимы/статусы и некорректные записи исключать с компактной причиной. Исключить дуэли.
4. Сохранять формулу и исходные показатели, дедуплицировать по `matchId`, привязать участие через отдельные UID/gpid, хранить разрыв при непересечении окон. Ограничить timeout/retry, параллельность, частоту и страницы; соблюдать ограничения провайдера.
5. Секрет и клиент держать только на сервере. Отключить подробное логирование библиотеки; её импорт сам создаёт каталог журналов. Probe изолирует эти файлы во временном каталоге и удаляет после проверки. Не запускать непрерывный цикл с недействительной сессией.
6. Только после сверки реальных ответов подключить адаптер к worker и объявлять интеграцию проверенной. До этого endpoint статуса должен честно сообщать о неподключённом источнике.
