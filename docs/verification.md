Потребление памяти после запуска: API около60МБ, worker44МБ, бот97МБ, Caddy18МБ; доступно около248МБ. Нагрузочная производительность этим не подтверждается.

- После подключения Pages к backend браузером проверены живые экраны на360/430/1280px: настоящий `/api/status` отвечает200 с `source_available:false`, нет ошибок CORS/JavaScript и горизонтального скролла. - На VPS повторно прошли35 исходных тестов; производственная миграция Alembic0001 успешно применена к PostgreSQL16. Проверены рестарт API/worker/bot, создание дампа и его восстановление в отдельную новую БД (revision0001, девять таблиц), после чего проверочная БД удалена. Восстановление не затрагивало рабочую БД.
- Telegram Bot API `getMe` подтвердил username `so2_check_bot`; `getWebhookInfo` — webhook отсутствует. Это проверка токена и настройки Telegram, не проверка игрового источника и не доказательство работы `/start`.
- GitHub-репозиторий `kugovv/so2-checker` создан; секреты перед публикацией проверяются по содержимому подготовленного набора файлов.
- GitHub Pages опубликован: `https://kugovv.github.io/so2-checker/`. Workflow публикации и workflow проверок (backend/frontend/Chromium UI) завершились успешно. Живая HTTPS-страница проверена в браузере на 360/430/1280 px: HTTP 200, без исключений JavaScript и горизонтального скролла; явно показывает неподключённый backend, без тестовой статистики.
- Telegram `setChatMenuButton` выполнен; `getChatMenuButton` подтвердил кнопку «Открыть приложение» и точный Pages URL. aiogram-бот запущен как `so2-check-bot`, рестартов по сбоям не было. Игровая интеграция этим не подтверждается.
- Backend: **38 pytest-тестов** проходят локально и в GitHub Actions. Проверены примеры средних1.12 и1.05, маленькая и пустая выборки, нулевые смерти, ассисты, цвета по округлённому значению, суммарный K/D и AVG, режимы, сохранение ID, изоляция настроек, подделка/давность initData, bearer-сессии, CORS, кэш/очередь, дедупликация, ошибки источника, пробелы и пагинация, состав топа, миграции Alembic upgrade/downgrade. Это тесты с изолированными фикстурами, не реальные игровые ответы.

Эмуляция уменьшения viewport проверяет раскладку, но не настоящую экранную клавиатуру телефона. Ответы API и Telegram SDK в этих проверках — изолированные тестовые фикстуры; в production их нет.

- Поля реального матча, их присутствие и точные dynamic property keys.
- История дальше 20 и реальные ограничения offset.
- Работа игровой интеграции: для UID202777998 получены только отказы доступа у внешних источников, реальные профиль и матчи не получены. Подробнее в `source-capabilities.md`.
- Реальный вход из Telegram Android/iOS: тестовая браузерная имитация Telegram SDK этого не доказывает.
- Нагрузка 10 тысяч пользователей и реальный объём игровых записей.
