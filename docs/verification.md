# Проверки 15.11.2026

## Подтверждено

- SSH-доступ к предоставленному VPS, Ubuntu 24.04, память/диск/занятые порты и работающие сервисы осмотрены. После изменения способа публикации развёртывание на VPS остановлено; приложение там не запущено.
- Telegram Bot API `getMe` подтвердил username `so2_check_bot`; `getWebhookInfo` — webhook отсутствует. Это проверка токена и настройки Telegram, не проверка игрового источника и не доказательство работы `/start`.
- GitHub-репозиторий `kugovv/so2-checker` создан; секреты перед публикацией проверяются по содержимому подготовленного набора файлов.
- GitHub Pages опубликован: `https://kugovv.github.io/so2-checker/`. Workflow публикации и workflow проверок (backend/frontend/Chromium UI) завершились успешно. Живая HTTPS-страница проверена в браузере на 360/430/1280 px: HTTP 200, без исключений JavaScript и горизонтального скролла; явно показывает неподключённый backend, без тестовой статистики.
- Telegram `setChatMenuButton` выполнен; `getChatMenuButton` подтвердил кнопку «Открыть приложение» и точный Pages URL. Описание бота явно сообщает незавершённость подключения backend и источника. Обработчик `/start` не запущен, полноценная работа бота не заявляется.
- Backend: 35 pytest-тестов проходят в локальном Python 3.12.10 на Windows. Проверены примеры средних 1.12 и 1.05, маленькая и пустая выборки, нулевые смерти, ассисты, цвета по округлённому значению, суммарный K/D и AVG, режимы, сохранение ID, изоляция настроек, подделка/давность initData, bearer-сессии, CORS, кэш/очередь, дедупликация, ошибки источника, пробелы и пагинация, состав топа, миграции Alembic upgrade/downgrade. Тестовые данные не являются реальными игровыми ответами.
- Локально запущен настоящий Uvicorn с отдельной SQLite-базой: `/healthz` отвечает 200 с `source_available:false`, `/api/status` честно описывает отключённый источник, `/api/me` без сессии отклоняется с 401.
- Probe компилируется и без handshake завершает работу с кодом 2 до подключения к игровому серверу.
- Astandy `0.3.0.2` установлен в отдельный локальный каталог зависимостей: импорт `StandClient`, protobuf-запросы разрешения UID/истории и сборщик схемы probe проверены в Python 3.12.10. Соединение с игрой не выполнялось; это не доказывает совместимость сетевого протокола.
- Frontend: TypeScript и production-сборка Vite проходят. В Playwright выполнены по 92 проверки в Chromium и WebKit (184 всего), ширины 360/390/430/1280. Проверены основные экраны, отсутствие горизонтального скролла, поиск без смены основного ID, участники, сравнение разных выборок, режимы, возврат, настройки, график по нажатию и пропуски, отсутствие данных/ошибки/загрузка, проценты и шесть границ цветов. Эмуляция уменьшения viewport проверяет раскладку, но не настоящую экранную клавиатуру телефона. Ответы API и Telegram SDK в этих проверках — изолированные тестовые фикстуры; в production их нет.

## Не подтверждено

- Авторизованный доступ к Standoff 2: действующий handshake не предоставлен.
- Поля реального матча, их присутствие и точные dynamic property keys.
- История дальше 20 и реальные ограничения offset.
- Работа интеграции, производственная PostgreSQL-миграция и рестарт сервисов приложения на хостинге: backend ещё не размещён.
- Реальный вход из Telegram Android/iOS: тестовая браузерная имитация Telegram SDK этого не доказывает.
- Нагрузка 10 тысяч пользователей и реальный объём игровых записей.

При запуске обновлять этот документ фактическими результатами, а не заменять непроверенные пункты успешной сборкой frontend.
