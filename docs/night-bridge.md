# SO2 Night Bridge: сервер protocol 1

HTTPS API: `https://so2-api.50.114.115.221.sslip.io`. Именно этот корневой адрес вводится в APK; не добавлять `/api` и не использовать GitHub Pages как backend. На каждый запрос APK добавляет отдельный Bearer-токен сборщика. Токены бота, игровые сессии и сессии Mini App не принимаются.

Маршруты: GET `/api/collector/v1/health`, POST `/api/collector/v1/jobs/claim`, POST `/api/collector/v1/jobs/{id}/frames`, POST `/api/collector/v1/jobs/{id}/complete`, POST `/api/collector/v1/events`. Формы запросов соответствуют `apk/night-bridge-source/so2-night-bridge/docs/API_CONTRACT.md` и текущему BridgeApi.java из APK 0.1.0. Пустая очередь возвращает 204 без тела, health — только `ok:true,protocol:1` после авторизации.

Для владельца создаётся отдельный случайный 256-битный секрет. В базе хранится SHA-256, а не исходный токен. При первом claim ключ атомарно связывается с UUID установки APK; другая установка отклоняется. Это привязка к предъявленному UUID и секрету, не аппаратная аттестация телефона. Регистрация и отзыв доступны только локальной команде администратора, публичного API выдачи ключей нет. Секреты и графический ключ не помещаются в frontend, Git, ответы API или журналы. Свободный текст событий и ошибок намеренно не сохраняется.

Подготовлены таблицы устройств, зарегистрированных ID, состояний профиля/режима, подписок, заданий, аренд, кадров, OCR-кандидатов и событий. Миграция 0004 добавляет их и nullable preferred_uid пользователя, сохраняя прежние привязки и данные. Непроверенный ID можно сохранить без выдуманного Player/ника; источник подтвердит существование позднее. Поиск не меняет основной ID. Смена ID не удаляет общие матчи прежнего профиля. До проверки не показываются фиктивные нули и пустые графики как реальные результаты.

Временная зона расписания — Europe/Moscow. Следующая дата вычисляется сервером. APK самостоятельно предупреждает в 23:30 МСК и запускает ночь в 00:00 МСК. Сервер материализует очереди только зарегистрированных профилей; основной ID и режим не создают повторных активных заданий для разных подписчиков. Сайт читает сохранённые данные, не управляя телефоном по каждому поиску. Дополнительные новые профили для просмотра ограничены пятью в день на пользователя. Обычная ночь пока выключена `COLLECTOR_SCHEDULE_ENABLED=false`, а claim ограничен пилотным UID. Включать массовую очередь можно лишь после калибровки и измерения реальной пропускной способности.

Аренда хранится в PostgreSQL, действует 30 минут и привязана к устройству и run_id. Истёкшая аренда сохраняет свои кадры в собственном каталоге; следующая начинает sequence с 0. Тому же run_id новая аренда того же задания не выдаётся, поскольку protocol 1 не передаёт lease_id. Запоздалые кадры и чужие run_id отклоняются. Повторы sequence/hash и complete идемпотентны. Каждое задание имеет максимум 20 матчей, 120 выданных действий и 25 кадров; действия проверяются по закрытой грамматике. Нельзя передать shell, JS, URL, пакет чужого приложения или команду блокировки.

На HTTP установлены ограничения до чтения/декодирования: 6 МиБ на кадр JSON, 4 МиБ на изображение, 12 Мп, два активных HTTP-приёма. Проверяются base64, SHA-256, JPEG/PNG, размеры и соответствие запрошенному capture. Изображение декодируется только изолированным ограниченным worker, которому не передаются секреты. OCR идёт последовательно в существующем worker. Сначала распознаётся ID матча/экран, затем полная таблица, если нет уже проверенного совпадения. Названия У/П/С приводятся к K/D/A существующим OCR, формулы рейтинга не меняются.

`captured` означает только передачу кадров. Неизвестный экран, отсутствие подтверждения игрового UID/режима/переходов и сомнительные поля дают needs_review/partial. Они не обновляют last_success_at, не превращаются в реальные матчи/рейтинг и не подменяют каноническую историю. Сохранённые прежние показатели и timestamps остаются доступными. Снимок и хеш не доказывают подлинность данных Axlebolt.

Первое тестовое задание намеренно содержит только launch_game, wait, capture текущего экрана и done. Поисковые координаты не выдуманы. Проверенного обхода Unity-интерфейса пока нет, поэтому полноценный сбор, ввод ID, разблокировка и минутный сквозной тест на физическом TECNO ещё не подтверждены. Accessibility не даёт доступа к памяти или закрытым файлам игры. Графический ключ остаётся только внутри APK, сервер никогда не запрашивает его.

Физическая проверка 16.11.2026: APK обратился к рабочему HTTPS API, установка связалась с отдельным ключом, получила задание, передала JPEG 2436×1080 и завершила его. Первый полученный кадр полностью чёрный; статус needs_review/CALIBRATION_REQUIRED, задание partial. Игровой профиль, ID, таблица и статистика на этом кадре не видны. Это подтверждение транспорта с телефона, а не рабочего обхода игры или минутного теста с разблокировкой. Нужен повторный снимок после появления видимого игрового меню; если он тоже чёрный, требуется исследование механизма снимка на этом телефоне. Ключ доступен владельцу через локальный файл «Скопировать ключ Night Bridge.cmd», который копирует секрет в буфер без вывода в консоль; ключ не публикуется в документации.

Кадры хранятся в `/var/lib/so2-check/collector/{job}/runs/{lease}/frames` с закрытыми правами. Срок хранения исходных обработанных кадров — 7 дней; хеши, метаданные, кандидаты и история не удаляются этой очисткой. Общая квота исходных снимков — 512 МиБ, резерв свободного диска — 512 МиБ. При исчерпании места запрос отклоняется; чужие каталоги не очищаются. Состояния, число переданных кадров, кандидатов и успешно проверенных профилей считаются отдельно.

Ручной импорт сохранён и включён. `MANUAL_IMPORT_ENABLED=false` закрывает запись на сервере и разбор в боте; чтение прежнего архива остаётся. Выключать его до реального сквозного теста нескольких профилей и повторного обновления без дублей нельзя. В базе manual/self_confirmed и collector/needs_review разделены. Топ в текущем проекте удалён.

Команды под окружением `/etc/so2-check/app.env`, из `/opt/so2-check/backend`:

```sh
python -m app.collector_cli status
python -m app.collector_cli enqueue-test --uid 202777998 --mode competitive
python -m app.collector_cli revoke-device --device DEVICE_PRINCIPAL_ID
systemctl status so2-check-api so2-check-worker so2-check-bot
journalctl --namespace=so2-check -u so2-check-api -u so2-check-worker --since today
systemctl start so2-check-backup.service
```

Регистрация: `python -m app.collector_cli register-device < private-device.json`; stdout сообщает только идентификатор устройства. Для восстановления используется обычный отдельный backup PostgreSQL приложения. Ключи коллектора не включены в Git. Исходники предоставленного APK лежат отдельно в папке apk, сам APK не переустанавливается без необходимости.
