# Зона 9 · Standoff Checker

Telegram Mini App для последних 20 матчей Standoff 2, собственного рейтинга и сравнения игроков. Поддерживаются только «Соревновательный» 5×5 и «Напарники» 2×2.

Опубликованный интерфейс: **https://kugovv.github.io/so2-checker/**. Бот: **https://t.me/so2_check_bot**. Backend: **https://so2-api.50.114.115.221.sslip.io**. API, PostgreSQL, очередь и aiogram-бот запущены на VPS отдельными сервисами; `/start` открывает приложение, кнопка меню настроена. Реальные игровые данные пока недоступны: первоначальный вход и продление игровой сессии ещё не реализованы.

**Статус:** автоматический игровой источник пока не подключён. Доступен отдельный разбор скриншотов итоговой таблицы: бот распознаёт игроков, предлагает проверить K/D/A и сохраняет подтверждённый матч. В профиле доступен личный лучший матч; общий топ удалён. Автоматический вход, MMR и глубина игровой истории остаются непроверенными. См. [исследование источника](docs/source-capabilities.md).

## Разбор скриншота и личный рекорд

Отправить боту `/match` либо сразу фото/файл JPEG, PNG или WebP с никнеймом в подписи. Ник можно прислать следующим сообщением. Выбрать свою строку и подтвердить K/D/A и режим; ошибки распознавания можно исправить. [Описание и ограничения](docs/screenshot-matches.md).

Подтверждённые матчи сохраняются в отдельный личный архив. Лучший матч показывается в профиле с картой, счётом и составами команд. Рекорды 5×5 и 2×2 независимы; новый строго более высокий рейтинг заменяет текущий. Для сопоставимости скриншотов и автоматических данных рекорд использует единый предварительный расчёт по K/D/A. Автоматическая выборка последних 20 матчей остаётся отдельной.

## Размещение

По указанию владельца интерфейс публикуется из этого репозитория на GitHub Pages, а backend размещён на предоставленном VPS. GitHub Pages обслуживает только статические файлы. API, PostgreSQL, очередь обновлений и бот работают из `/opt/so2-check`; другие приложения VPS не изменены. Токены не должны находиться в Pages, Actions build variables или frontend.

- `frontend/`: React, TypeScript, Vite, Recharts, локальные файлы Manrope с кириллицей.
- `backend/`: FastAPI, SQLAlchemy, Alembic, PostgreSQL; отдельные worker и aiogram bot.
- `backend/game_client/`: отдельный серверный TLS/RPC-клиент чтения, [возможности и ограничения](docs/server-client.md).
- `infra/`: установленные шаблоны изолированных systemd-сервисов, API reverse proxy и резервного копирования.
- `tools/probe_source.py`: проверка реального клиента по файлу игровой сессии.
- `.github/workflows/`: тесты и публикация Pages.

## Локальные проверки

```sh
cd frontend
npm ci
npm run build
cd ../backend
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install -r game_client/requirements.txt
.venv/bin/python -m pytest -q
```

В Windows Python виртуального окружения находится в `.venv/Scripts/python.exe`. Тестовые данные из `backend/tests/` используются только тестами, production их не импортирует. Проверка браузером с тестовыми ответами также не подтверждает реальную интеграцию.

Браузерные проверки на 360/390/430/1280 px находятся в `tools/ui-smoke.cjs`. Установить `npm ci --prefix tools`, затем браузеры: `node tools/node_modules/playwright/cli.js install chromium webkit` с переменной `PLAYWRIGHT_BROWSERS_PATH`, указывающей на абсолютный путь `.pw-browsers` в корне проекта. Запустить frontend через `npm run dev` и в другом терминале `node tools/ui-smoke.cjs`. Для WebKit задать `PW_ENGINE=webkit`. Скрипт допускает только localhost, подменяет ответы лишь внутри тестового браузера и сохраняет скриншоты/отчёт в `artifacts/ui/`. Эти фикстуры не подключаются к опубликованному приложению. Chromium-проверки также запускаются в GitHub Actions.

## GitHub Pages

В настройках репозитория Pages → Source выбирается GitHub Actions. Workflow `pages.yml` собирает `frontend/dist` и публикует HTTPS-страницу. `base: './'` позволяет открыть приложение в подпапке проекта. В Repository variables `VITE_API_URL` задаётся публичный HTTPS-адрес отдельно запущенного backend **без** `/api` в конце. Если переменная отсутствует, приложение сообщает о ненастроенном backend и не использует фиктивный API.

Обновление интерфейса — push проверенного кода в `main`; Actions пересобирает и публикует Pages. Для изменений `VITE_API_URL` требуется повторный запуск публикации.

Оценка Android-сборщика: [вместимость VPS и сохраняемые проекты](docs/server-capacity.md),
[проверенные и непроверенные способы доступа к данным](docs/data-access-audit.md).
Ручной workflow `Manual Android boot test (no game login)` проверяет отдельный
GitHub-hosted Android без установки игры и ввода учётных данных. Успешный boot
не подтверждает игровую авторизацию или работоспособность источника.
Следующий ручной тест `Signed game startup compatibility`
проверяет точную подпись APK и запуск в выбранном режиме сети. Offline —
строгий режим по умолчанию; отдельный online-тест проверяет только старт
приложения без ввода аккаунта. Автоматическое сетевое поведение игры при
этом не объявляется отсутствующим. Учётные данные в эти workflows не
передаются; никакой из тестов не является production-сборщиком.
Профиль `apkpure-xapk-203982` отдельно проверяет полный пакет с main OBB:
фиксированный SHA256 архива, безопасная распаковка, проверка подписи APK,
размера и SHA256 переданного OBB. Аккаунт в этом тесте не вводится;
снимки экрана и живой процесс сами по себе не доказывают вход и доступ к матчам.

## Backend и безопасность

Скопировать `.env.example` в закрытый конфигурационный файл выбранного backend-хостинга. `PUBLIC_URL` — полный адрес опубликованного Mini App, `ALLOWED_ORIGINS` — его origin (например, `https://OWNER.github.io`, без подпапки). Секрет `BOT_TOKEN` хранится только на backend. `DATABASE_URL` указывает на отдельную БД с отдельной ролью.

Сначала выполнить `alembic upgrade head` из `backend/`. Затем запустить API `uvicorn app.main:app`, worker `python -m app.worker`, бот `python -m app.bot`. Backend должен обслуживаться через HTTPS. Детали эксплуатации: [docs/operations.md](docs/operations.md).

Исходный Telegram `initData` проверяется сервером HMAC-SHA256 с токеном конкретного бота, сроком не более 300 секунд и проверкой даты в будущем. Сессия случайная, ограничена сроком, в БД хранится её хеш. Для раздельных origin сессионный bearer хранится только в памяти frontend. Вне Telegram обхода входа нет. Настройки определяются серверным Telegram ID; просмотр другого UID не меняет основной профиль и не подтверждает владение игровым аккаунтом.

## Расчёты и история

[Методика рейтинга](docs/rating.md) предварительная, не является официальным HLTV Rating. Исходные показатели, параметры, версия формулы и результат сохраняются. Главный рейтинг — простое среднее последних 1–20 матчей текущего режима. Сохранённый архив его не заменяет. K/D считается по суммам, AVG — убийства на матч, HS% — по суммам убийств в голову и убийств. Отсутствующие показатели не превращаются в нули.

Нормы 5×5 и 2×2 раздельные. Без личных сыгранных раундов используется явно обозначенная предварительная оценка за матч. В личном рекорде обе категории источников сравниваются одним вариантом расчёта по K/D/A. Поправка на силу противников пока отключена. Нет выдуманного ADR, KAST или событийных метрик.

История хранится с начала наблюдения, дедуплицируется по ID матча и участнику. Полнота архива не предполагается. Возможные пропуски помечаются, неизвестные участки графиков не считаются непрерывными. Матчи автоматически не удаляются; политика объёма описана в эксплуатационной документации.
